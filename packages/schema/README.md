# Maine configuration format

This package defines the one file Maine writes: the saved host list. It is
versioned JSON, it is deliberately small, and it is the contract between every
Maine client — the macOS application today, and the Windows, Linux and Android
clients later.

Nothing else is shared between clients. There is no account and no service of
ours; a client writes this file, reads it back, and that is the whole local
storage story. Optional sync moves the *encrypted vault*, never this file:
the server sees only opaque bytes and this format is always written locally.

## Where the file lives

| Platform | Location (planned or in use)                        |
| -------- | --------------------------------------------------- |
| macOS    | `~/Library/Application Support/Maine/hosts.json`     |
| Linux    | `$XDG_CONFIG_HOME/maine/hosts.json` (planned)        |
| Windows  | `%APPDATA%\Maine\hosts.json` (planned)               |
| Android  | app-private `passwords.maine` vault (no plaintext file) |

Each client owns its own file. Sync, when enabled, moves the encrypted vault as
an opaque blob and never this plaintext format.

## The file

```json
{
  "schemaVersion": 1,
  "hosts": [
    {
      "id": "0f8fad5b-d9cb-469f-a165-70867728950e",
      "name": "Web server",
      "hostname": "203.0.113.10",
      "port": 22,
      "username": ""
    }
  ]
}
```

The canonical definition is [`hosts.schema.json`](hosts.schema.json) (JSON Schema
2020-12).

### Top level

| Field | Type | Required | Meaning |
| ----- | ---- | -------- | ------- |
| `schemaVersion` | integer | yes | Always `1` for this revision. A client **must** refuse a file whose version is higher than it implements, and must not overwrite it. |
| `hosts` | array of host | yes | The saved hosts, in the order the user arranged them. There is no limit on the number of entries. |

### Host

| Field | Type | Required | Meaning |
| ----- | ---- | -------- | ------- |
| `id` | string | yes | Stable identifier, generated by the client. A lowercase UUID string is recommended. Clients must not derive meaning from it and must not change it when other fields are edited. |
| `name` | string | yes | The label shown in the host list. 1–128 characters. |
| `hostname` | string | yes | What is handed to OpenSSH as the connection target: an IP address, a DNS name, or a `Host` alias defined in the user's own `~/.ssh/config`. No whitespace, no leading `-`. 1–253 characters. |
| `port` | integer | yes | 1–65535. `22` means "default": clients **should** omit the `ssh -p` flag so a matching `~/.ssh/config` stanza can choose the real port. |
| `username` | string | yes | 1–128 characters. The empty string means "not specified": clients **should** omit the `ssh -l` flag so OpenSSH can take the user from `~/.ssh/config`, from the key that authenticates, or from the local user name. |

### What is not in the file, on purpose

* **Passwords.** Never stored, never asked for by Maine. If a host needs one,
  OpenSSH prompts inside the terminal.
* **Private keys, key paths, passphrases.** Authentication belongs to
  `~/.ssh`, `ssh-agent` and `~/.ssh/config`. Maine runs the `ssh` client the user
  already has, so existing keys keep working without being copied anywhere.
* **Known hosts, proxy commands, port forwards.** All of that stays in
  `~/.ssh/config`, where OpenSSH applies it. Maine only records what the user
  typed into its own sidebar.

## Reading and writing

* **Writers must** emit every required field of every host, even when the value
  is a default (`"port": 22`, `"username": ""`).
* **Readers should** treat a missing or `null` `port` or `username` as the
  default (`22` and `""`) so a hand-edited file still loads. Any other type
  mismatch is an error the client must report without discarding the file.
* **Writers must** save atomically, so an interrupted write cannot leave a
  half-written file behind.
* **Writers should** write the file with permissions that keep it readable only
  by the user (`0600` on POSIX systems).
* Unknown properties are not allowed by the schema. A client that wants to add
  one must bump `schemaVersion` and document the migration.

## Versioning policy

`schemaVersion` is a single integer that covers the whole document.

* **Adding a required field, changing a field's meaning, or removing a field**
  requires a new version number and a documented migration path for readers.
* **Adding an optional field** still requires a new version number, because
  older readers reject unknown properties.
* Clients must keep reading every version they have shipped support for, and
  must leave a file from a newer version untouched.

A version 2 example lives in
[`examples/hosts.invalid-version.json`](examples/hosts.invalid-version.json); it
exists so the validator can prove that clients reject it.

## Validating a file

`tools/validate.py` checks a file, or a directory of files, against the schema.
It uses only the Python standard library.

```sh
python3 tools/validate.py                     # validates every example
python3 tools/validate.py ~/Library/Application\ Support/Maine/hosts.json
python3 tools/validate.py --schema hosts.schema.json some-file.json
```

The script supports the keywords this schema uses (`type`, `required`,
`properties`, `additionalProperties`, `items`, `$ref`, `const`, `enum`,
`minLength`, `maxLength`, `minimum`, `maximum`, `pattern`). It refuses to run
against a schema that uses a keyword it does not implement, so it can never
report a file as valid because it skipped a constraint.

Files whose name contains `.invalid` are expected to be rejected; everything
else must pass. The command exits non-zero if that is not the case.

## Implementing a client

A conforming client:

1. Reads the file, or starts with an empty host list when it does not exist.
2. Validates it against `hosts.schema.json` before using it.
3. Refuses (and never rewrites) a file with a higher `schemaVersion`.
4. Applies the `port`/`username` defaults described above.
5. Builds an `ssh` command line from the host and lets the system OpenSSH client
   do everything else: keys, agent, `ProxyJump`, `Match`, and so on.
6. Writes the whole file back after every change, atomically.
