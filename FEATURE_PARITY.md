# Maine feature parity report

**Audited:** 2026-10-12 · revision `4f8be8c` (branch `main`, clean tree)
**Clients:** macOS (Swift/SwiftUI, reference), Android (Kotlin/Compose)
**Note:** The Windows client was removed from the repository after this audit; its findings were dropped.
**Method:** source-level audit of the two clients, their tests, and the shared
contract in `packages/schema`. macOS tests are covered by CI; nothing was
re-executed for this report.

Legend: ✅ implemented / parity · ⚠️ partial, divergent, or defective · ❌ missing · — not applicable

---

## 1. Executive summary

The load-bearing contracts are in good shape: both clients implement the
same version-2 vault envelope byte-for-byte, both key sessions by session
UUID, and both keep "close deletes the encrypted record first / quit keeps
records" semantics. macOS is the complete reference; Android reimplements the
same feature set with platform-native pieces.

The gaps are concentrated in one place:

1. **Android session/host management UX is incomplete.** Session rename and
   close-all exist in the session layer and are tested, but no UI calls them;
   host duplicate is missing; host delete has no confirmation; the username is
   required in the editor although the model allows blank.

Smaller but consistent themes: `~/.ssh/config` reading is ported and tested on
every client but not wired to any user-visible behavior anywhere; diagnostics
exist only on macOS; Android has no launcher icon, About/version, or
empty-state text, and backgrounding does not lock the vault.

## 4. Android — findings in detail

### 4.1 Session management UX

- **No rename UI:** `SessionManager.renameSession` is implemented and tested
  (`SessionManager.kt:70-84`, `SessionManagerTest.renamePersists...`) but no
  composable calls it. `grep rename` over `ui/` finds nothing.
- **No Close Every Session UI:** `SessionManager.closeAll()` exists
  (`SessionManager.kt:286-292`) with no caller; `CloseAllForHost` also runs only
  as part of deleting a host.

### 4.2 Host management UX

- **No duplicate host** action (macOS has one).
- **Delete has no confirmation:** the trash icon calls straight through to
  `viewModel.deleteHost` (`HostListScreen.kt:247-252`); there is no
  `AlertDialog` anywhere in the app. On a phone this is a one-tap destructive
  action.
- **Username is required by the editor** (`HostEditorDialog.kt:136-139`) even
  though the model and macOS allow blank (ssh config decides).
  Password auth makes this defensible, but it is a deliberate divergence and
  should be documented.
- **Search** matches name and hostname only, not username
  (`HostListScreen.kt:110-120`); macOS matches all three.
- **No empty state** when the host list is empty.

### 4.3 Ported but unwired code (docs drift)

`SshTarget` (`ssh/SshTarget.kt`) and `SshConfigFile` (`ssh/SshConfigFile.kt`)
have tests but no app callers: the live sshj transport dials
`host.hostname/port/username` directly. `apps/android/README.md` says the
config reader is "ported for host import and display resolution", which today
is not true. Either wire it into the editor/header or label it as a port only.

### 4.4 Platform polish

- **No launcher icon:** no `android:icon` in the manifest and no mipmap
  resources; the device shows the default Android icon.
- **No About / version UI** (`versionName = "1.0.0"` is never displayed).
- **Backgrounding does not lock** the vault (`MainActivity.onStop` only
  checkpoints scrollback); SSH sessions keep running in the background by
  design, but the derived key stays in memory until the explicit Lock or
  process death.
- **Auth scope:** password only — no keys, agent, or certificates, which is
  documented but means key-only hosts cannot be reached from Android at all.
- **Host-key re-trust requires deleting the host** (pinned keys are keyed by
  host UUID and there is no pin management UI). Documented, but worth a
  discoverable action.

### 4.5 Strengths worth noting

Real vendored VT emulator with the SSH byte stream (no JNI), one-shot
CTRL/ALT + ESC/TAB/arrows row, resize coalescing, ANSI replay with
reply-suppression and alternate-screen reset, TOFU host-key pinning with
`ssh-keygen`-comparable fingerprints, OSC-52 clipboard, Material 3 themes with
a Maine terminal palette, golden-vault interop test.

## 5. macOS — notes on the reference client

macOS implements everything the other client targets, except:

- **ssh-config reader and resolver are dead code.** `SSHConfigFile`,
  `Host(sshConfigEntry:)` and `SSHTarget.resolved(using:)` are fully tested but
  called from nowhere in `Sources`. `docs/architecture.md` describes the
  resolver as display-only; the display never uses it. There is also no import
  UI, here or on any client.
- **Docs claim interactive password prompting that the code refuses.**
  `docs/architecture.md:76-78` says that without a saved password "OpenSSH
  prompts inside the terminal as usual", but `TerminalSession.connect()`
  refuses with "This host needs a saved password. Edit the host to add one."
  (`TerminalSession.swift:147-151`). Since every editor requires a password,
  this only affects migrated/legacy hosts — but the doc and the code disagree.
- **`packages/schema/README.md` is stale.** It describes a plaintext
  `hosts.json` as "the one file Maine writes"; the shape now lives inside the
  encrypted vault payload.
- No terminal find UI (SwiftTerm exposes find actions; unexposed here), same as
  Android. Delete acts without confirmation (also on Android).
- Diagnostics are the macOS-only differentiator: metadata-only JSONL logging,
  opt-in via menu/`MAINE_DEBUG`/`--debug`, geometry probes, disconnect
  snapshots, strict no-secrets policy enforced by tests.

## 6. Suggested order of work

1. **Android session/host UX** — wire the existing rename and close-all logic,
   add duplicate host, add a delete confirmation, drop the editor's username
   requirement (or document it).
2. **Decide on the unwired ssh-config work** — wire import/resolution on both
   clients or remove/label the dead code; today it is tested code that no user
   can reach, and the READMEs overstate it.
3. **Polish parity** — Android launcher icon + About/version + empty state,
   terminal search on both clients; refresh stale docs (`architecture.md`
   password claim, `packages/schema/README.md`).
4. **Copy credentials on Android** — mirror the macOS
   **Host → Copy Credentials** action (also on a host's right-click menu):
   copy a plain-text block with one field per line and only the fields that
   exist, in this order:

   ```
   [ip] <hostname>
   [port] <port>          (only when the port is not 22)
   [username] <user>      (only when set)
   [password] <password>  (only when saved and the vault is unlocked)
   ```

   A locked vault must request the master password first (or omit the password
   line and say so); never log the copied text, and keep the format identical
   across clients so pasted blocks look the same. macOS reference:
   `Models/CredentialText.swift` + `App/CredentialCommands.swift`.
