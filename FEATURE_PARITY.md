# Maine feature parity report

**Audited:** 2026-10-12 · revision `4f8be8c` (branch `main`, clean tree)
**Clients:** macOS (Swift/SwiftUI, reference), Windows (C#/WPF, .NET 8), Android (Kotlin/Compose)
**Method:** source-level audit of the three clients, their tests, and the shared
contract in `packages/schema`. Windows WPF/ConPTY/WebView2 behavior was verified
by code inspection (no Windows host in this audit); the WPF runtime source was
consulted where startup behavior mattered. macOS and Windows Core tests are
covered by CI; nothing was re-executed for this report.

Legend: ✅ implemented / parity · ⚠️ partial, divergent, or defective · ❌ missing · — not applicable

---

## 1. Executive summary

The load-bearing contracts are in good shape: all three clients implement the
same version-2 vault envelope byte-for-byte, all three key sessions by session
UUID, and all three keep "close deletes the encrypted record first / quit keeps
records" semantics. macOS is the complete reference; Windows and Android both
reimplement the same feature set with platform-native pieces.

The gaps are concentrated in three places:

1. **The Windows terminal cannot load.** `terminal.html` references
   `./lib/xterm.js` etc., but `Terminal/lib/` is neither committed nor copied to
   the build output, and `fetch-xterm.sh` pins a version of the fit addon that
   does not exist on npm. A built Windows app opens a blank terminal pane.
2. **Windows session restore loses scrollback.** Restore reads the saved history
   from the vault but never displays it, and the 2-second checkpoint immediately
   overwrites the saved record with the live (initially empty) buffer. The
   Windows README row "Session snapshots + auto-reconnect after unlock | done" is
   not true in the current code.
3. **Android session/host management UX is incomplete.** Session rename and
   close-all exist in the session layer and are tested, but no UI calls them;
   host duplicate is missing; host delete has no confirmation; the username is
   required in the editor although the model allows blank.

Smaller but consistent themes: `~/.ssh/config` reading is ported and tested on
every client but not wired to any user-visible behavior anywhere; diagnostics
exist only on macOS; Windows lacks Close Every Session and a launch-time reset
of its DPAPI session key; Android has no launcher icon, About/version, or
empty-state text, and backgrounding does not lock the vault.

## 4. Windows — findings in detail

### 4.1 ❌ Terminal libraries are never packaged (critical)

- `src/Maine.App/Terminal/terminal.html:6,14-15` loads `./lib/xterm.css`,
  `./lib/xterm.js`, `./lib/xterm-addon-fit.js`.
- `Terminal/lib/` does not exist in the repository, and `Maine.App.csproj:27-29`
  copies only `Terminal/terminal.html` to the output. Nothing copies `lib/**`.
- `scripts/fetch-xterm.sh:14` pins `@xterm/addon-fit@5.5.0`; npm has no such
  version (stable addon-fit releases are 0.9.0–0.11.0; 5.5.0 is the core
  `@xterm/xterm` version). The documented vendoring step fails before the copy
  bug is even reached.
- Consequence: a built app shows an empty terminal pane (`Terminal is not
  defined`), no keyboard input, no resize reporting. CI only compiles, so it
  never notices.

**Fix:** pin `@xterm/addon-fit@0.11.0`, add
`<None Include="Terminal\lib\**" CopyToOutputDirectory="PreserveNewest" />`,
and add a CI check that the output contains `Terminal/lib/xterm.js`.

**Status (2026-10-12):** fixed. `scripts/fetch-xterm.sh` now takes the two
versions separately (`@xterm/xterm@5.5.0`, `@xterm/addon-fit@0.11.0`), copies
`xterm.css` from its real `package/css` location, `Maine.App.csproj` copies
`Terminal\lib\**\*` to the output, and the Windows CI job fails if any of the
three assets is missing from the build output. Verified in a browser against
the vendored files; the two packages' UMD globals (`Terminal`, `FitAddon`)
match what `terminal.html` uses.

### 4.2 ❌ Restored scrollback is neither shown nor kept (high)

`SshSessionManager.Restore` (`SshSessionManager.cs:298-321`) passes
`record.History` to `Connect(..., restoredHistory: record.History)`. `Connect`
uses it only for the final `PersistSession(session, restoredHistory)` call; it
never seeds `SshSession.History` (initialized empty at `SshSessionManager.cs:35`).
The WebView's `restore` message (`MainWindow.xaml.cs:408-417`) reads
`session.History`, so it is empty at startup. Within 2 seconds,
`Checkpoint()` (`SshSessionManager.cs:288-296`) calls `PersistSession(session)`
with the live buffer and overwrites the saved record — the pre-restart
scrollback is destroyed. This contradicts `apps/windows/README.md:78`.

**Fix:** seed `session.History` from the saved record (or post the saved text to
the terminal) during `Restore`, and skip the first checkpoint until new output
has arrived.

### 4.3 ⚠️ Exit-event race on close and reconnect (medium)

`ConPtySession.Exited` fires from a wait thread (`ConPtySession.cs:161-173`) and
the handler only checks whether the session is still in `Sessions`
(`SshSessionManager.cs:206-211`), not whether the process that exited is still
the session's process.

- `Close` (`:139-157`) deletes the vault record, then kills, then removes the
  session. An `Exited` that lands in between re-runs `PersistSession` and can
  resurrect a record that was just deleted.
- `Reconnect` (`:125-135`) kills the old process while the session stays
  registered; the old process's `Exited(255)` can set `Disconnected`/`Failed`
  and leave a stale "ssh exited with code 255" banner, racing the new
  connection's `Connecting` state.

**Fix:** compare the exiting `ConPtySession` against `session.Process` and
ignore mismatches; set an explicit "stopping" flag for intentional kills.

### 4.4 ⚠️ DPAPI unlock key is not reset on launch (medium, invariant)

macOS deletes its session key on every launch (`AppState.prepareForLaunch` →
`PasswordStore.lock()`) and on quit/lock. Windows deletes its
`%LOCALAPPDATA%\Maine\vault-keys\<vault>.bin` only from `VaultStore.Lock()`
(`VaultStore.cs:171-176`, called from lock and quit). `App.OnStartup` does
nothing else (`App.xaml.cs:7-17`), so a key file left behind by a crash or
kill persists at rest, and `VaultStore.GetPassword`/`GetHosts` will decrypt
with it without the master password (`VaultStore.cs:383-403`). After a crash,
cancelling the unlock prompt can therefore still populate the host list from
the stale key. This breaks the documented "current session only" lifetime of
the helper key.

**Fix:** delete stale key files at startup, before the unlock prompt.

### 4.5 ⚠️ Askpass helper constructs the main window (medium)

`App.xaml:4` sets `StartupUri="MainWindow.xaml"`. In helper mode,
`App.OnStartup` calls `Shutdown(AskPassHelper.Run())` and returns without
clearing `e.PerformDefaultAction` (`App.xaml.cs:7-17`). WPF's
`Application.DoStartup()` loads the StartupUri after `OnStartup` unless
`PerformDefaultAction` is false (verified against dotnet/wpf's
`Application.cs`), so every askpass invocation — including passphrase and
host-trust prompts — constructs `MainWindow` and with it `VaultStore`,
`SshSessionManager` and its 2-second snapshot timer, and can briefly flash
the Maine window.

**Fix:** set `e.PerformDefaultAction = false;` before `Shutdown(...)`.

### 4.6 Host and session UX gaps

- **Rename input is masked:** `PromptDialog.xaml:8` uses a `PasswordBox` for
  session rename (`MainWindow.xaml.cs:317-323`); the user cannot see the name
  they are typing. Use a `TextBox` for non-secret prompts.
- **No Close Every Session:** the Session menu has New/Reconnect/Close only
  (`MainWindow.xaml:24-28`); macOS has "Close Every Session".
- **Status dot never updates:** a literal gray `Ellipse` (`MainWindow.xaml:79-80`);
  state appears only as text.
- **Header ignores ssh config:** `MainViewModel.cs:64-65` calls
  `Resolved(new SshConfigFile(), null)`, so hostname/user/port from
  `%USERPROFILE%\.ssh\config` are never shown.
- **Host editor copy contradicts behavior:** "Leave the password blank to let
  OpenSSH prompt inside the terminal", but a blank password is rejected on save
  (`HostEditorWindow.xaml.cs:48-54`).
- **`StripForScrollback` byte-vs-char slice** (`SshSessionManager.cs:260-272`):
  for non-ASCII history the byte count can exceed 1 MiB while the char count
  does not, and `stripped[^MaxHistoryBytes..]` then throws — silently swallowed
  by the `catch` in `PersistSession`, so the snapshot is skipped. `1 MiB` is
  also counted in chars during append.

### 4.7 ❌ Missing diagnostics

No debug logging, snapshot, or `--debug` path exists in Windows code; the
README's "not started" is accurate. macOS is the only client with diagnostics.

## 5. Android — findings in detail

### 5.1 Session management UX

- **No rename UI:** `SessionManager.renameSession` is implemented and tested
  (`SessionManager.kt:70-84`, `SessionManagerTest.renamePersists...`) but no
  composable calls it. `grep rename` over `ui/` finds nothing.
- **No Close Every Session UI:** `SessionManager.closeAll()` exists
  (`SessionManager.kt:286-292`) with no caller; `CloseAllForHost` also runs only
  as part of deleting a host.

### 5.2 Host management UX

- **No duplicate host** action (macOS and Windows both have one).
- **Delete has no confirmation:** the trash icon calls straight through to
  `viewModel.deleteHost` (`HostListScreen.kt:247-252`); there is no
  `AlertDialog` anywhere in the app. On a phone this is a one-tap destructive
  action.
- **Username is required by the editor** (`HostEditorDialog.kt:136-139`) even
  though the model and the other clients allow blank (ssh config decides).
  Password auth makes this defensible, but it is a deliberate divergence and
  should be documented.
- **Search** matches name and hostname only, not username
  (`HostListScreen.kt:110-120`); macOS matches all three.
- **No empty state** when the host list is empty.

### 5.3 Ported but unwired code (docs drift)

`SshTarget` (`ssh/SshTarget.kt`) and `SshConfigFile` (`ssh/SshConfigFile.kt`)
have tests but no app callers: the live sshj transport dials
`host.hostname/port/username` directly. `apps/android/README.md` says the
config reader is "ported for host import and display resolution", which today
is not true. Either wire it into the editor/header or label it as a port only.

### 5.4 Platform polish

- **No launcher icon:** no `android:icon` in the manifest and no mipmap
  resources; the device shows the default Android icon.
- **No About / version UI** (`versionName = "1.0.0"` is never displayed).
- **Backgrounding does not lock** the vault (`MainActivity.onStop` only
  checkpoints scrollback); SSH sessions keep running in the background by
  design, but the derived key stays in memory until the explicit Lock or
  process death.
- **Auth scope:** password only — no keys, agent, or certificates, which is
  documented but means key-only hosts cannot be reached from Android at all.
- **Host-key re-trust requires deleting the host** (pinned keys are keyed by
  host UUID and there is no pin management UI). Documented, but worth a
  discoverable action.

### 5.5 Strengths worth noting

Real vendored VT emulator with the SSH byte stream (no JNI), one-shot
CTRL/ALT + ESC/TAB/arrows row, resize coalescing, ANSI replay with
reply-suppression and alternate-screen reset, TOFU host-key pinning with
`ssh-keygen`-comparable fingerprints, OSC-52 clipboard, Material 3 themes with
a Maine terminal palette, golden-vault interop test.

## 6. macOS — notes on the reference client

macOS implements everything the other clients target, except:

- **ssh-config reader and resolver are dead code.** `SSHConfigFile`,
  `Host(sshConfigEntry:)` and `SSHTarget.resolved(using:)` are fully tested but
  called from nowhere in `Sources`. `docs/architecture.md` describes the
  resolver as display-only; the display never uses it. There is also no import
  UI, here or on any client.
- **Docs claim interactive password prompting that the code refuses.**
  `docs/architecture.md:76-78` says that without a saved password "OpenSSH
  prompts inside the terminal as usual", but `TerminalSession.connect()`
  refuses with "This host needs a saved password. Edit the host to add one."
  (`TerminalSession.swift:147-151`). Since every editor requires a password,
  this only affects migrated/legacy hosts — but the doc and the code disagree.
- **`packages/schema/README.md` is stale.** It describes a plaintext
  `hosts.json` as "the one file Maine writes" (and the Windows row says
  "planned"); the shape now lives inside the encrypted vault payload, and the
  Windows client has been real for a while.
- No terminal find UI (SwiftTerm exposes find actions; unexposed here), same as
  the other clients. Delete acts without confirmation (Windows confirms).
- Diagnostics are the macOS-only differentiator: metadata-only JSONL logging,
  opt-in via menu/`MAINE_DEBUG`/`--debug`, geometry probes, disconnect
  snapshots, strict no-secrets policy enforced by tests.

## 7. Suggested order of work

1. **Windows terminal packaging** (§4.1) — without it the Windows client cannot
   be used at all. One-line version fix + one csproj item + a CI check.
2. **Windows session restore** (§4.2) — makes the advertised snapshot/restore
   behavior real; small, contained change in `SshSessionManager.Restore`.
3. **Windows lifecycle fixes** — exit-event race (§4.3), DPAPI launch reset
   (§4.4), askpass `PerformDefaultAction` (§4.5); each is a few lines and
   protects a documented invariant.
4. **Android session/host UX** — wire the existing rename and close-all logic,
   add duplicate host, add a delete confirmation, drop the editor's username
   requirement (or document it).
5. **Decide on the unwired ssh-config work** — wire import/resolution on all
   three or remove/label the dead code; today it is tested code that no user
   can reach, and the READMEs overstate it.
6. **Windows small fixes** — rename `TextBox`, Close Every Session, live status
   dot, header resolution, editor copy.
7. **Polish parity** — Windows diagnostics ("not started"), Windows clipboard,
   Android launcher icon + About/version + empty state, terminal search on all
   clients; refresh stale docs (`architecture.md` password claim,
   `packages/schema/README.md`, Windows README parity row).
8. **Copy credentials on Windows and Android** — mirror the macOS
   **Host → Copy Credentials** action (also on a host's right-click menu):
   copy a plain-text block with one field per line and only the fields that
   exist, in this order:

   ```
   [ip] <hostname>
   [port] <port>          (only when the port is not 22)
   [username] <user>      (only when set)
   [password] <password>  (only when saved and the vault is unlocked)
   ```

   A locked vault must request the master password first (or omit the password
   line and say so); never log the copied text, and keep the format identical
   across clients so pasted blocks look the same. macOS reference:
   `Models/CredentialText.swift` + `App/CredentialCommands.swift`.
